# Предметна область та логічна схема

Система обліковує каталог книжкового магазину, залишки, покупців, замовлення
та їхні позиції. Облікові записи персоналу й читачів відокремлені від карток
покупців: реєстрація користувача не створює автоматичного комерційного замовлення.

## Сутності та ключі

| Таблиця | Первинний ключ | Зовнішні ключі | Призначення |
|---|---|---|---|
| authors | author_id | - | Основний автор книги, ім’я, прізвище, країна |
| categories | category_id | - | Унікальна назва категорії та опис |
| books | book_id | author_id, category_id | ISBN, назва, рік, поточна ціна та залишок |
| customers | customer_id | - | ПІБ, унікальний email, телефон, дата реєстрації |
| orders | order_id | customer_id | Чернетка, підтверджене або скасоване замовлення |
| order_items | (order_id, book_id) | order_id, book_id | Кількість і зафіксована ціна продажу |
| app_users | user_id | - | Унікальні логін/email, хеш пароля, роль, активність, хеш API-токена |
| activity_log | log_id | user_id, допускає NULL | Виконавець, операція, ключ запису, знімки до/після, час |

## Зв’язки

- Автор 1:N книги; у навчальній моделі кожна книга має одного основного автора.
- Категорія 1:N книги.
- Покупець 1:N замовлення.
- Замовлення M:N книги через order_items.
- Користувач 1:N події журналу; для SQL з pgAdmin або анонімної операції
  user_id може бути NULL, а username зберігає ім’я виконавця події.

## Третя нормальна форма

Операційні таблиці відповідають 3НФ:

1. Поля основних сутностей атомарні; повторювані позиції замовлення винесено
   в окрему таблицю.
2. В authors, categories, books, customers, orders та app_users атрибути
   залежать від повного первинного ключа.
3. Для order_items кількість та ціна продажу залежать від повної пари
   (order_id, book_id). unit_price не є поточною ціною каталогу: одна книга
   може продаватися в різних замовленнях за різними цінами й зі знижками.
4. Ім’я автора та назва категорії не дублюються в books; контактні дані
   покупця не дублюються в orders.
5. Сума замовлення обчислюється в order_summary, а не зберігається разом
   із незалежно редагованими позиціями.

Журнал є подієвим сховищем: username та JSONB-знімки навмисно фіксують
історичний стан, а не дублюють актуальні довідникові дані для редагування.
Паролі й хеші API-токенів у знімках відсутні.

## Обмеження та транзакції

- PRIMARY KEY, FOREIGN KEY, NOT NULL, UNIQUE та CHECK захищають структуру.
- Для видалення батьків довідників і книг із продажами використано RESTRICT.
- Видалення дозволеної чернетки каскадно видаляє її позиції.
- Чернетка не резервує товар. При підтвердженні перевіряються всі залишки.
- confirm_order та cancel_order блокують книги в порядку book_id.
- Повторне підтвердження або скасування відхиляється.
- Клієнтські ролі: reader - перегляд; manager - створення/редагування та
  обробка замовлень; admin - також видалення, керування ролями й backup.
- Перевірки доступу виконуються сервером у спільному сервісному шарі.
